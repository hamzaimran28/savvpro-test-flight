# AI usage disclosure — FlightHub

This document summarizes how **AI coding assistants** were used while building and polishing FlightHub, for transparency in reviews and assessments.

---

## Which tools were used

- **Cursor** (IDE) with **Composer / agent-style** assistants (GPT-family and/or Claude-class models routed by Cursor — exact model revisions vary by session and subscription).

No separate paid API keys were required beyond what Cursor provides inside the editor.

---

## Representative prompts / themes

High-level prompts that shaped substantial work included:

1. **UI/UX polish** — “Improve FlightHub dashboard: tighter layout, card sections, typography, buttons, flights table hover, booking form grouping, seat map as hero element, badges, loading/toasts, responsive CSS — **plain HTML/CSS/JS only**, no React/Tailwind.”
2. **Dark theme** — “Dark themed UI; white background doesn’t look nice.”
3. **Seat semantics & feedback** — “Available seats green, booked red; overlay confirmation after booking/cancel/other important actions; clarify reload vs client refresh.”
4. **Edge cases** — “Handle cancelling an **already cancelled** booking (friendly UX vs generic error).”
5. **Automated testing** — “Add **pytest** with isolated DB, **TestClient**, three business tests (inventory 409, cancel restores inventory, search filters), subprocess integration of **`scripts/verify_*.py`**.”
6. **Documentation sweep** — “Finalize README, USER_GUIDE, AI_USAGE, update ARCHITECTURE; ensure runs from clean clone, tests pass, meaningful git hygiene.”

## Mistakes or weak patches generated by AI (and corrections)

| Issue | What went wrong | How it was corrected |
|--------|-----------------|---------------------|
| **CSS syntax** | During a `:root` variable edit, a nested `code { ... }` block was accidentally pasted **inside** `:root`, which is invalid CSS. | Removed nesting; restored a proper top-level `code` rule in `frontend/public/css/app.css`. |
| **Stale DB session binding in pytest** | `SessionLocal` was imported at **test module load time**, so seeded rows targeted the **default** SQLite URL while **`TestClient`** used the **reloaded** isolated DB — bookings saw “flight not found.” | Obtained **`SessionLocal` inside each test** (or via a `_session_local()` helper) **after** the `client` fixture reloads `app.db.session`. |
| **Heavy-handed UX duplication** | Both a **banner** and **overlay** fired for some outcomes initially. | Kept overlays for substantive API outcomes; left inline/banner cues for lightweight validation messages. |
| **Inventory invariant under concurrency** | Concurrent booking script occasionally saw **`Flight.seats_available`** disagree with **`derive_seats_open`** after many parallel commits. | Added **`flight_service.reconcile_flight_inventory(session, flight_row)`** immediately after flushing the new **Booking**, before **`commit`** in **`create_booking`**, aligning the persisted counter with catalogue-derived occupancy. |

These fixes were validated with **`python -m pytest`** and **`scripts/verify_overbooking_concurrency.py`**.

---

## How AI improved development speed

- **Iteration on CSS/layout** — Faster exploration of spacing, hierarchy, seat-map styling, and dark-theme tokens without scaffolding a CSS framework build.
- **Boilerplate** — Quick stubs for overlays, legends, toast-like banners, pytest layout, subprocess script tests.
- **Cross-layer reasoning** — Helped relate backend **409** semantics to frontend messaging (e.g. “already cancelled” as **informational** overlay).
- **Documentation throughput** — Consistent structuring of README, USER_GUIDE, architecture updates, and this disclosure file.

All AI-suggested behavior was **verified** against the running API, browser UI where relevant, and the automated suites before treating it as finished.
